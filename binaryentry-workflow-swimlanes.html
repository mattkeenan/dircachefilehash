Key Data Structures:

  • binaryEntry: Raw 68-byte binary structure in mmap memory
  • binaryEntryRef: Safe pointer wrapper with offset + IndexFile reference
  • BinaryEntryInterface: Interface for entry access (implemented by binaryEntryRef)
  • skiplistWrapper: Zero-copy skiplist for ordered entry management
  • retireSkiplist: Entries ready for retirement, ordered by path order ID
  • pathOrderToEntry map: Path order ID → BinaryEntryInterface lookup for completions
  • hashJobStart: Hash job submission structure (JobID + file path)
  • hashJobComplete: Hash completion structure (JobID + computed hash)
  • IoVec: Vectorio structure for efficient bulk writes

Key Coordination Mechanisms

  • Path Order ID Sequencing: Ensures path order preservation through async hash processing
  • Retire Skiplist: Holds completed entries until sequential retirement possible
  • Non-blocking Completion: Prevents goroutine coordination deadlocks
  • JobID Tracking: Links hash jobs to specific entries via algorithmHashManager
  • pathOrderToEntry Map: Bridges async completion notifications to entry references
  • Channel Coordination: hashJobChan → workers → completionChan → parking

Critical Sequencing Rules

  • Path order ID assignment must be atomic and sequential
  • Retirement from retireSkiplist must be strictly sequential (1, 2, 3, ...)
  • Hash completions can arrive out-of-order but writes must be in-order
  • Unchanged files bypass hashing but maintain sequence position
  • pathOrderToEntry map is cleaned up immediately after entry is added to retire queue
